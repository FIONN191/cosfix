# M1 实现计划：跑通主链路

目标：拖一张场照进去，看到本地指标面板 + 八维度诊断报告。

范围限定在 [设计文档](../specs/2026-07-27-cosfix-design.md) 的 M1：输入界面 + 本地指标 + 单图诊断 + 一家 provider + Electron 壳。**提示词生成、参考图对比、历史档案、网页壳都不在本期**。

---

## 开工前需要确认

- [x] **不需要 API key**。M1 走 CLI 通道，用本机已装的 `codex`（`/Applications/ChatGPT.app/Contents/Resources/codex`，走 ChatGPT 订阅额度）。已验证 `codex exec -i <图片> "<提示词>"` 支持附加图片、非交互运行。备用通道 `qwen`（`~/.npm-global/bin/qwen`，支持 `-o json`）。
- [ ] **测试图**：Step 2 的指标单测用程序生成的合成图（纯色、渐变、噪声、过曝欠曝），不依赖真实场照，可以先开工。但 Step 4 之后需要几张你自己的场照做真实验证——放 `test/fixtures/private/`，已 gitignore。

## Step 0 — 脚手架

沿用 Prompt Vault Pro 的技术栈：Vite + React + TypeScript + Tailwind 4，Electron + electron-builder 包壳，Vitest 跑单测。

- [ ] `npm init`，装依赖
- [ ] Vite + React + TS + Tailwind 4 配置
- [ ] Electron 主进程与 preload 骨架
- [ ] Vitest 配置
- [ ] `.claude/launch.json` 加 `cosfix` 预览配置，端口 5178（5177 被 prompt-vault 占了）

**验收**：`npm run dev` 起得来页面，`npm run test` 空跑通过。

## Step 1 — `src/lib/image.ts` 图片管线

- [ ] File → ImageBitmap → OffscreenCanvas 解码，拿到原图 `ImageData`
- [ ] HEIC 检测与转码（转不了就明确报错，不静默失败）
- [ ] 生成长边 1536px 副本 → base64，供 API 调用
- [ ] EXIF 解析（用 `exifr`），读不到时返回 `null` 不抛错

**注意**：指标必须在**原图** `ImageData` 上算，副本只用于上传。这两条路径不能混。

**验收**：拖入一张图，控制台打出原图尺寸、EXIF、副本体积。

## Step 2 — `src/lib/metrics/` 本地指标

八个纯函数模块，统一签名 `(imageData: ImageData) => 该项结果`，不碰 DOM 不碰网络。

- [ ] `histogram.ts` — RGB/亮度直方图、p5/p50/p95、高光暗部裁切率、平均亮度、RMS 对比度
- [ ] `whiteBalance.ts` — 灰世界法 → `direction` + `magnitude`（**只报方向和幅度，不输出开尔文值**）
- [ ] `skin.ts` — YCbCr 粗筛（Cb 77–127, Cr 133–173）→ 覆盖率 + HSV 均值 + verdict，采样不足返回 `insufficient-sample`
- [ ] `sharpness.ts` — 拉普拉斯方差 → soft / normal / oversharpened
- [ ] `noise.ts` — 平滑区标准差估计
- [ ] `palette.ts` — k-means k=5，输出 hex + 占比
- [ ] `composition.ts` — 亮度重心（归一化坐标）+ 地平线倾斜角
- [ ] `exif.ts` — EXIF 字段归一化
- [ ] `index.ts` — 汇总成 `LocalMetrics`

**验收**：Vitest 快照测试全绿，测试图用程序生成的合成图（`test/fixtures/synthetic/`，可提交）。

## Step 3 — `src/lib/channels/` + `transport.ts`

M1 只做 CLI 通道，HTTP 通道留到 M4，但接口现在就统一。

- [ ] `channels/index.ts` — `Channel` 接口定义（`available()` / `call()`）+ 注册表
- [ ] `channels/cli/detect.ts` — 探测本机可用 CLI。**不能只查 `PATH`**：codex 在 `/Applications/ChatGPT.app/Contents/Resources/codex`，要显式查这个位置
- [ ] `channels/cli/codex.ts` — 拼 `codex exec -i <临时图> "<提示词>"`，读 stdout，解析 JSON，清理临时文件
- [ ] `channels/cli/qwen.ts` — 备用通道，`qwen -p "<提示词>" -o json`
- [ ] `transport.ts` — 运行时环境判断，Electron 分支走 `window.cosfix.invokeChannel`
- [ ] `electron/main.ts` — `ipcMain.handle('channel:call')` → `spawn` 子进程 → 回传；带超时和非零退出处理
- [ ] `electron/preload.ts` — 只暴露必要接口
- [ ] 设置页：显示探测结果（装了哪些 CLI、登录没有），选默认通道，「测试连接」按钮

**硬规矩**：渲染层不得直接 `fetch` 外部 API 也不得 `spawn`，一律走 transport。这条现在守住，M4 加 HTTP 通道、M5 加网页壳时才不用返工。

**注意**：CLI 子进程要设超时（诊断类调用给 120s），超时后 kill 并透出 stderr 前几行，不要静默挂死。

**验收**：设置页正确探测出 codex 和 qwen，点测试连接能拿到模型回复。

## Step 4 — `src/lib/diagnose/` 诊断

- [ ] `framework.ts` — 八维度定义 + 系统提示词。**这是本项目的核心，值得反复打磨**：要把 cos 专属项（假发边缘与发际线、美瞳反光死板、妆面还原、服装材质廉价感与穿帮、道具塑料感、背景现代元素穿帮、角色氛围契合度）写得足够具体，模型才不会输出泛泛而谈的套话。
- [ ] `schema.ts` — 输出 JSON schema，强约束 `Finding` 结构
- [ ] `run.ts` — 组装 payload（1536px 副本 + `LocalMetrics` + 状态开关 + 备注）→ transport → 解析 → `DiagnosisReport`，通道无关
- [ ] 非法 JSON 时把解析错误回喂给模型重试一次；仍失败展示原始文本，不静默丢弃
- [ ] `findings` 按 `priority` 排序，不按维度字母序

**验收**：真实场照跑通，拿到结构化报告，`fixability` 三档都出现过。
